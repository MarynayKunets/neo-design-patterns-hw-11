# Домашнє завдання №11

## Поведінкові патерни: Ланцюжок відповідальностей та Посередник

### Опис проєкту

У цьому проєкті реалізовано систему обробки структурованих даних із використанням поведінкових патернів проєктування:

- Ланцюжок відповідальностей (Chain of Responsibility)
- Посередник (Mediator)

Програма зчитує записи з файлу `records.json`, виконує їх перевірку та обробку, після чого зберігає результати у відповідні вихідні файли.

Підтримуються такі типи записів:

- `access_log`
- `transaction`
- `system_error`

Некоректні записи зберігаються у файл `rejected.jsonl`.

---

## Реалізація патерну «Ланцюжок відповідальностей»

Патерн реалізовано в директорії `chain`.

Для кожного типу запису створено окремий ланцюг обробки:

### AccessLogChain

- TimestampParser
- UserIdValidator
- IpValidator

### TransactionChain

- TimestampParser
- AmountParser
- CurrencyNormalizer

### SystemErrorChain

- TimestampParser
- LevelValidator
- MessageTrimmer

Кожен обробник виконує лише одну відповідальність і передає запис наступному елементу ланцюга.

---

## Реалізація патерну «Посередник»

Патерн реалізовано класом `ProcessingMediator`.

Посередник централізовано керує збереженням результатів та маршрутизацією записів до відповідних модулів запису:

- AccessLogWriter
- TransactionWriter
- ErrorLogWriter
- RejectedWriter

Таким чином бізнес-логіка обробки не залежить від логіки збереження результатів.

---

## Розширення системи

Для додавання нового типу записів необхідно:

1. Додати новий тип у `DataRecord.ts`.
2. Створити необхідні обробники.
3. Створити новий ланцюг обробки.
4. Реалізувати відповідний Writer.
5. Зареєструвати новий тип у `handlerMap`.
6. Додати підтримку нового Writer у `ProcessingMediator`.

Завдяки використанню патернів «Ланцюжок відповідальностей» та «Посередник» система легко розширюється без зміни вже існуючої логіки.
